2   RBAC Wiring Gaps (Surface by Surface)

Each gap references the exact file and what needs to change.

canAccess() is dead code — never called Critical
lib/plan.ts exports canAccess(href, plan, role) which correctly defines all agent-blocked routes. However it is not imported or called anywhere in the codebase. The route guard is fully designed but entirely inert — agents can navigate to /dashboard/team directly.
Fix: Import canAccess in Sidebar.tsx nav item renderer and in each page that should self-guard (Team page, Settings billing/routing).
Sidebar “Invite team” shows on all plans & roles Medium
The “Invite team” link in Sidebar.tsx:275 is always rendered regardless of plan or role. A solo user sees it; a teams agent sees it.
Fix: Wrap in plan === 'teams' && role === 'admin' check.
Team page action buttons — no role gate Medium
app/dashboard/team/page.tsx:891 renders “+ Add agent” and “Assign N leads” with no check on getRole(). Agent-role users on a teams plan can see and click both. Agent card edit / remove / toggle actions (:437) have the same omission.
Fix: Read getRole() in the page component and conditionally render admin-only actions.
Team Analytics shows all agents to any teams user Medium
app/dashboard/team/analytics/page.tsx is correctly paywalled for non-teams plan. But once inside, the agent scorecard shows every agent's row to any role, including agents. An agent should only see their own row.
Fix: Filter scorecard rows to m.id === currentUserId when role === 'agent'.
API data scope — admin sees only own leads Post-migration
/api/insights and /api/crm/leads both filter WHERE agent_id = userId. Correct for solo and agent roles. But a teams admin needs to see all leads in the workspace. No workspace-scoped bypass exists yet (workspace_id column is in migration-012 but not live).
Fix: After workspace migration ships, add admin bypass: omit agent_id filter when role === 'admin' and plan === 'teams'.
Plan & role are localStorage-only (client-side) Root cause
All RBAC enforcement reads localStorage.getItem('leadgap-plan') and localStorage.getItem('leadgap-role'). Any user can open DevTools and set themselves to admin or teams. No server-side validation. The profiles table already has a role column — the DB foundation is there but not wired to the session.
Fix: After Supabase workspace migration: read role from profiles.role via session JWT or a bootstrap query on login. Replace localStorage reads in lib/plan.ts.

3   Security Vulnerabilities

Threats ordered by severity. High items should be fixed before first paying customer.

3.1   Unauthenticated API Routes High

The following routes have no auth check and use getAdminClient() (service role — bypasses RLS). Any internet user who discovers the URL can read or write production data.

Route Exposure Impact Fix
POST /api/seed Open to anyone Flood DB with fake leads; wipes real data on re-run Add requireAdminSecret guard or disable in production via env flag
GET/POST /api/brochures
GET/DELETE /api/brochures/[id]		 Open to anyone Anyone can list, upload, or delete brochures (property docs) Add requireAuth() to all methods
GET/POST/PATCH /api/crm/leads/[id]/tasks Open to anyone knowing a lead UUID Read/write tasks on any lead without login Add requireAuth(); verify lead belongs to caller
GET /api/market-news Open to anyone Minor (read-only), but leaks business context Add requireAuth()
POST /api/calculations/share Open to anyone Anyone can create share links attributed to any user Add requireAuth()
GET/POST /api/seed/brochures Open to anyone Can seed/overwrite brochure data without login Add requireAdminSecret or remove endpoint

3.2   Ingest Webhook Forgery Medium

Portal ingest routes have no signature verification Medium
/api/ingest/magicbricks, /api/ingest/housing, /api/ingest/facebook, /api/ingest/99acres — all accept POST requests with no secret token or HMAC signature check. An attacker can POST fake lead payloads directly, flooding the leads table with garbage data. Compare with /api/billing/webhook which correctly verifies Razorpay HMAC.
Fix: Add a shared INGEST_WEBHOOK_SECRET env var. Each ingest route checks x-portal-secret header matches. Configure the same token in each portal's webhook settings dashboard. (Pattern: same as billing webhook signature verification.)

3.3   Service Role Key Fallback to Public Anon Key Medium

SUPABASE_SERVICE_ROLE_KEY falls back to NEXT_PUBLIC_SUPABASE_ANON_KEY Medium
In app/api/leads/[id]/activities/route.ts:6 and app/api/seed-dashboard-data/route.ts:6:

const supabaseServiceKey = process.env.SUPABASE_SERVICE_ROLE_KEY || process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!

The NEXT_PUBLIC_ prefix makes the anon key visible in the browser bundle. While the anon key is intended to be semi-public (it's rate-limited), using it as a fallback for service-role operations means RLS is not bypassed, and writes that depend on the service role will silently fail or use wrong permissions.
Fix: Remove the fallback. If SUPABASE_SERVICE_ROLE_KEY is missing, return a 503 like the rest of the codebase does via getAdminClient(). Never silently downgrade to the anon key on a server route.

3.4   document.write in Print Window Low / Informational

InsightsKit.tsx uses document.write for print output Low
components/insights/InsightsKit.tsx:690 opens a new window and calls w.document.write(…) to render the print view. The content is controlled (no user-supplied HTML injected), so XSS risk is low. However, document.write is deprecated in modern browsers and may fail silently in future Chrome versions.
Fix (future): Replace with URL.createObjectURL(new Blob([html], {type:'text/html'})) and open that URL instead.

5   Ordered Remediation Plan

Work through these in order. Phase 1 should be done before the first paying team customer onboards. Phase 2 before public launch. Phase 3 is post-launch hardening.

Phase 1 — Before first team customer

  • Guard /api/seed with requireAdminSecret app/api/seed/route.ts — Add the same requireAdminSecret(request) call used in /api/seed-dashboard-data. Without this, any internet user can flood the production DB.
  • Add requireAuth to /api/brochures and /api/crm/leads/[id]/tasks Both routes use getAdminClient() (service role, bypasses RLS) with zero authentication. Three lines at the top of each handler fixes this.
  • Remove service-role fallback to anon key app/api/leads/[id]/activities/route.ts:6 and app/api/seed-dashboard-data/route.ts:6 — Delete the || process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY! fallback. Return 503 if service role key is absent.
  • Wire canAccess() into the Sidebar Import canAccess from lib/plan.ts in Sidebar.tsx and pass it to the nav item renderer. Currently the function is dead code. This immediately blocks agents from navigating to the Team page.
  • Gate “Invite team” sidebar link to teams+admin Sidebar.tsx:274–299 — Wrap the link in plan === 'teams' && role === 'admin'.
  • Gate Team page mutating actions on role === 'admin' app/dashboard/team/page.tsx:889–891 — Read getRole() and conditionally render “+ Add agent”, “Assign leads”, and agent card edit / remove / toggle buttons.

Phase 2 — Before public launch

  • Add ingest webhook secret verification Create env var INGEST_WEBHOOK_SECRET. All four ingest routes (magicbricks, housing, facebook, 99acres) check x-portal-secret header. Configure the same token in each portal's webhook dashboard.
  • Add requireAuth to /api/market-news and /api/calculations/share Both are low-risk read/write routes but should not be open to unauthenticated callers.
  • Filter Team Analytics scorecard by role app/dashboard/team/analytics/page.tsx — When role === 'agent', filter the agent scorecard table to only show rows where member.id === currentUserId.
  • Fix vendor TypeScript errors ShaderBackground.tsx null-guards, NcrMap.tsx type replacement, Silk.tsx @types/three install. Keeps tsc --noEmit at zero errors, which makes future regressions obvious.

Phase 3 — After Supabase workspace migration ships

  • Move plan + role source of truth from localStorage to Supabase session Read profiles.role on login and store in React context (not localStorage). This is the only fix that makes RBAC server-enforceable.
  • Add workspace-scoped admin lead query /api/insights and /api/crm/leads — When role === 'admin' and plan === 'teams', remove the agent_id = userId filter and replace with workspace_id = userWorkspaceId so the admin sees all workspace leads.
  • Add server-side route guards to protect pages Team page, Billing, Lead Routing settings — use Next.js middleware or redirect() in server components to block by role fetched from DB, not localStorage.
